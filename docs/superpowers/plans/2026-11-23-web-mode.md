# Web Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a desktop-browser "web mode" to YL-Private-Agents: an on-phone HTTP server whose JSON snapshot + SSE stream drives a single-page chat UI (send/stop/continue, model/reasoning, tool approvals, workspace picker, settings) authenticated by a per-run access code.

**Architecture:** Copy YL-COS's `webaccess/` package (hand-rolled `ServerSocket` HTTP server in a `specialUse` foreground service) and `assets/web-access/` SPA as the base, retargeted to package `com.ylprivate.agents.webaccess`. Rewrite `WebAccessBridge` against our `ChatViewModel`/`AgentEngine` (chat-core action subset only). Push our Compose theme (`Color.kt`/`PaletteColors.kt`) into the browser as CSS variables in every snapshot. Register `WebAccessForegroundService` in the manifest. Add a `SettingsWebAccessScreen` section wired into `SettingsHome`.

**Tech Stack:** Kotlin, Android SDK 37 (minSdk 26, targetSdk 36), Java 17 toolchain, kotlinx.coroutines (already a dependency), no new Gradle dependencies.

**Spec:** `docs/superpowers/specs/2026-11-23-web-mode-design.md` — the plan argues from that spec; read both before executing.

## Global Constraints

- `minSdk 26`, `targetSdk 36`, `compileSdk 37` (our `app/build.gradle.kts`).
- Java 17 toolchain; Kotlin compiles to JVM-8-compatible bytecode.
- No new Gradle dependencies — `kotlinx.coroutines.core` already available.
- `INTERNET`, `ACCESS_NETWORK_STATE`, `FOREGROUND_SERVICE_SPECIAL_USE`, `FOREGROUND_SERVICE`, `WAKE_LOCK` already declared in manifest; only `WebAccessForegroundService` registration is new.
- Brand tokens untouched: package `com.ylprivate.agents`, theme `Theme.YLPrivateAgents`, scheme `ylprivateagents` (anti-goal #4).
- v1 scope = chat-core actions only (`send`, `stop`, `continue`, `model`, `reasoning`, `autoApproval`/`approval`/`question`, `tool`, `mcpSave`/`mcpEnabled`/`mcpRefresh`, `compression`/`compress`, `browseWorkspace`/`workspace`/`projectCreate`, `upload`, session CRUD). Deferred: subagent/prompt CRUD, project rename/pin/archive, voice settings (builder-check Q1 → A).
- `/api/upload` wired to existing `ChatViewModel` upload plumbing — no dedicated `UploadedFileManager` (builder-check Q2 → A).
- Access code generated randomly at each server start, held in memory, shown/copyable/resettable in settings, NOT persisted (builder-check Q3 → A).
- `WebAccessManager` activity-scoped, created in `MainActivity`, server stops with task (builder-check pile-2 #1).
- English UI only; full localization deferred (builder-check pile-2 #4).
- Copied YL-COS files carry AGPL-3.0 provenance — private use only; keep original copyright headers, document in `THIRD_PARTY_NOTICES.md`.

## Review Focus

| Failure mode / input | Expected behavior | Pinned by task |
|---|---|---|
| Bind port already in use | Server reports error in settings UI, does not crash | Task 4 (`WebAccessManager.start` error path) |
| Missing bearer token on `/api/action` | `401 Unauthorized`, login page shown | Task 6 (`WebAccessBridge.action` auth) |
| `sessionRevision`/`conversationId` mismatch vs phone | `409` "switched on the phone, refresh" | Task 6 (`requireSession`) |
| SSE client disconnects mid-stream | Stream ends cleanly, no leaked thread | Task 4 (`serveEvents` finally) |
| Foreground service on Android 14+ specialUse | Starts, keeps phone awake, stops with task | Task 3 (service registration + manifest) |
